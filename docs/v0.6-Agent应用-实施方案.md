# v0.6.0 ·「Agent 应用」实施方案

> 定位：把 WeaveCanvas 从「人手点按钮的流水线工具」升级为「会自己干活的数字剧组」。
> 对标 OiiOii 的多 Agent 剧组，但**复用现有全部后端能力**，不重写生产链路。
> 状态：**P0 + P1 核心已落地**（v0.6.0）—— 名册 / 运行台 / 时间线 / 确认闸门 / 预算护栏 /
> 断点续跑 / SSE 实时事件流 / 15 个工具。P2（delegate 多 Agent 串场）与 P3（运行报告）待做。
> 验收：`npm test`（47 项后端端到端）+ `npm run test:ui`（27 项无头浏览器验收）。

---

## 一、要解决什么问题

现状（v0.5.0）生产一集漫剧，用户要手动走 **6 步、点十几次按钮**：

| 步骤 | 现在怎么触发 |
| --- | --- |
| ① 写剧本 | 创作台一句话 → 自动写 |
| ② 提取角色 | 剧本页点「② 从剧本提取角色」 |
| ③ 提取场景 | 接口已有，前端入口弱 |
| ④ 拆分镜 | 剧本页点「① 一键拆分镜」 |
| ⑤ 合成提示词 | 生产线页勾选镜头 → 智能合成 |
| ⑥ 批量生图 | 分镜页点「⚡ 批量生图」 |
| ⑦ 批量视频 | 分镜页点「🎞 批量视频」 |
| ⑧ 导出成片 | 分镜页点「🎬 导出成片」 |

**「Agent 应用」要做的**：用户说一句「把《万世仙尊》第 3 章做成一集 8 镜的成片」，
一个（或一组）Agent 自己按顺序调用上面这些能力，跑完并把成片交出来；
用户全程只需在**关键节点点确认**，以及最后验收。

**一句话定义**：给现有流水线套一层会思考、会调用工具、会被拦住的执行外壳。

## 二、关键设计决策（先看这三条，不同意后面的都得改）

### 决策 1：用「提示词约定 + JSON 解析」做工具调用，不用原生 function calling

原因很硬：`server/endpoint.js` 的三种协议只构造 `messages` / `max_tokens`，
**没有任何 `tools` 字段透传**。原生 function calling 依赖网关支持，
而本项目要兼容「自建中转站 / Ollama / 各种国产网关」，一旦走原生 tools，
一半网关会直接报错。

所以采用**提示词内约定协议**，绕开网关差异：

```
你每轮只能输出一个 JSON 对象，不要有其它文字：
{"thought":"这一步为什么这么做","action":"工具名","args":{...}}
或
{"thought":"...","final":"给用户的最终答复"}
```

- 解析复用项目里已经打过补丁的 `pipeline.parseJsonLoose` / `extractObjects`
  （它们能吃下被 `max_tokens` 截断的输出——这是本项目踩过坑的地方，不要另写一套）
- 解析失败 → 把错误原文回灌给模型，**最多纠错 2 次**，仍失败则终止并保留现场
- 预留升级位：`ai_config` 加 `supports_tools` 标记，将来某网关支持原生调用时可切换

### 决策 2：工具只做「现有后端函数的薄封装」，不新增 AI 能力

所有工具直接调用 `server/pipeline.js` / `server/export.js` 里已有的函数，
`server/tools.js` 只是注册表（名字 + 描述 + 参数 + 执行器 + 结果摘要器）。
**零重复实现，零行为分叉**——Agent 画出来的图和用户手点的图必然一致。

### 决策 3：默认「半自动」，涉及花钱的工具必须确认

生图/生视频是**真花钱且不可逆**的。默认 `auto_run = 0`：

- 只读 + 文本类工具（查状态、拆镜、提角色）→ 自动执行
- 产生额度的工具（生图/生视频/多版本）→ 停下等用户确认
- 用户可对某个 Agent 打开「全自动」开关，但仍受预算护栏约束

**交互要点**

- 时间线每步是一张可折叠卡片，四种样式：`💭 思考`（灰）/ `🔧 工具`（蓝，带参数摘要）/
  `👁 观察`（绿，带结果摘要）/ `❓ 确认`（黄）/ `✗ 失败`（红，卡片内直接给「重试这一步」）
- 生图/生视频工具的观察卡片**内联缩略图**，不跳页
- 支持「从这一步重跑」：把该步之后的步骤标记为作废，从该步状态恢复（断点续跑依赖 `agent_step` 表）
- 视觉复用现有 CSS 变量与 `.prod-*` / `.oii-*` 类名，不引入新设计语言

## 四、数据模型（3 张新表，走 `CREATE TABLE IF NOT EXISTS`，向后兼容）

```sql
-- 剧组名册：一个 Agent 就是一次可复用的"岗位 + 人设 + 权限 + 预算"
CREATE TABLE IF NOT EXISTS agent (
  id TEXT PRIMARY KEY,
  name TEXT, role TEXT, avatar TEXT,
  system_prompt TEXT,            -- 岗位人设（主编剧/分镜师/美术指导…）
  model_id TEXT,                 -- 留空则用全局文本模型
  tools_json TEXT,               -- 允许调用的工具名单（权限白名单）
  auto_run INTEGER DEFAULT 0,    -- 0=花钱前必确认，1=全自动
  budget_json TEXT,              -- {maxSteps,maxImages,maxVideos,deadlineSec}
  builtin INTEGER DEFAULT 0,
  sort_order INTEGER DEFAULT 0,
  create_time TEXT, update_time TEXT
);

-- 一次运行
CREATE TABLE IF NOT EXISTS agent_run (
  id TEXT PRIMARY KEY, agent_id TEXT, script_id TEXT,
  goal TEXT,                     -- 用户那句目标
  status TEXT,                   -- running | waiting | done | failed | stopped
  step_count INTEGER DEFAULT 0,
  cost_json TEXT,                -- {images,videos,llmCalls,tokens}
  context_json TEXT,             -- 滑动窗口后的上下文快照（可续跑）
  error TEXT,
  create_time TEXT, update_time TEXT
);

-- 每一步（断点续跑、时间线渲染、审计都靠它）
CREATE TABLE IF NOT EXISTS agent_step (
  id TEXT PRIMARY KEY, run_id TEXT, seq INTEGER,
  role TEXT,                     -- thought | action | observation | ask | final
  tool TEXT, args_json TEXT, result_json TEXT,
  tokens INTEGER, ms INTEGER,
  status TEXT, error TEXT,       -- ok | failed | pending_confirmation
  create_time TEXT
);
CREATE INDEX IF NOT EXISTS idx_agent_step_run ON agent_step(run_id, seq);
```

**种子数据（`db.js` 的 `seed()` 里补一段）**：预置 5 个岗位，用户开箱即用、可改名可改提示词。

| 岗位 | 人设要点 | 工具白名单 | 自动 |
| --- | --- | --- | --- |
| 制片人 | 统筹进度、决定先后顺序、检查预算与成片完整性，最终交付 | 全部（含 `ask_user`/`finish`） | 否 |
| 编剧 | 只写剧本正文与梗概，不碰画面 | `get_project_state` `write_script` `ask_user` | 是 |
| 分镜师 | 拆镜、控节奏、写运镜；每镜时长 3-8 秒 | `split_shots` `update_shot` `compose_prompts` `ask_user` | 是 |
| 美术指导 | 角色形象锁定 + 场景锁定 + 风格一致性 | `extract_characters` `extract_scenes` `set_style` `update_character` `update_scene` `ask_user` | 是 |
| 剪辑师 | 出图出片与成片导出，管淘汰重做 | `generate_image` `batch_images` `batch_videos` `generate_variants` `select_variant` `export_movie` `ask_user` | **否** |

## 五、后端改动

### 新增 `server/tools.js` — 工具注册表

```js
export const TOOLS = {
  get_project_state: {
    desc: '查看当前剧本的字数、镜头数、角色/场景清单、已出图/出片数量。每轮开始时建议先调用。',
    args: { scriptId: 'string? 默认当前剧本' },
    kind: 'read',                        // read | text | image | video  → 决定要不要人工确认
    run: async (args, ctx) => {...},     // 薄封装，直接调 pipeline / q
    brief: (r) => `剧本 ${r.words} 字 / ${r.shots} 镜 / 角色 ${r.cast} 个 / 已出图 ${r.images}`,
  },
  write_script:      { kind: 'text',  ... },  // → callLLM（复用 /generate 的 system 提示词）
  extract_characters:{ kind: 'text',  ... },  // → pipeline.extractCharacters
  extract_scenes:    { kind: 'text',  ... },  // → pipeline.extractScenes
  split_shots:       { kind: 'text',  ... },  // → pipeline.splitScript
  compose_prompts:   { kind: 'text',  ... },  // → 复用 /compose 的提示词专家 system
  update_shot:       { kind: 'read',  ... },  // 改画面/台词/运镜/时长/出镜角色/场景
  update_character:  { kind: 'read',  ... },
  update_scene:      { kind: 'read',  ... },
  set_style:         { kind: 'read',  ... },
  generate_image:    { kind: 'image', ... },  // → pipeline.generateShotImage
  generate_variants: { kind: 'image', ... },  // → shot_variant 多版本
  select_variant:    { kind: 'read',  ... },
  batch_images:      { kind: 'image', ... },  // 内部走 MAX_PARALLEL=2 队列
  batch_videos:      { kind: 'video', ... },
  export_movie:      { kind: 'read',  ... },  // → exporter.exportMovie
  delegate:          { kind: 'text',  ... },  // P2：把子任务派给另一个岗位 Agent
  ask_user:          { kind: 'read',  ... },  // 主动求助/请求确认
  finish:            { kind: 'read',  ... },  // 结束并给交付总结
};
```

**结果摘要器 `brief` 是省 token 的关键**：观察回灌给模型的**只有摘要**，
绝不回灌 base64 或完整 JSON（生图只回 `{shotId, url, prompt 前 40 字}`）。

### 新增 `server/agents.js` — 编排循环

```
run(agent, { goal, scriptId })
  └─ loop (step < budget.maxSteps)
       ├─ 组装上下文：岗位人设 + 目标 + 剧本现状 + 工具清单 + 最近 N 步摘要
       ├─ callLLM  → 拿 JSON 决策
       ├─ 解析（parseJsonLoose → extractObjects 兜底 → 纠错重问 ≤2 次）
       ├─ 决策分派
       │    ├─ final          → 落库、status=done、发 done 事件
       │    ├─ ask_user       → status=waiting，发 ask 事件，挂起等人
       │    ├─ 工具.kind 需确认 && !auto_run → status=waiting，发 confirm 事件
       │    └─ 执行工具        → 落 agent_step(observation)、发 step 事件
       └─ 护栏检查：步数 / 生图数 / 生视频数 / deadline
            └─ 任一触顶 → 软停止（保留现场、可续跑），发 stopped 事件
```

**四个工程细节（不做的话这个功能会很脆）**

1. **上下文压缩**：历史超 8 步时，把更早的步骤压成一行 `[第3步] split_shots → 8 镜`，
   原文明细留在 `agent_step` 表里，前端时间线照常完整展示。
2. **幂等**：`update_shot` / `set_style` 这类写操作天然幂等；
   `split_shots` 必须先查「已存在镜头数」再决定覆盖还是追加，**避免重复拆镜堆镜头**
   （v0.3.0 踩过这个 bug，`splitScript` 的调用方要沿用现有的覆盖前确认逻辑）。
3. **续跑**：`POST /api/agent-runs/:id/resume` 从最后一条 `status != ok` 的步骤重放，
   已完成步骤不重做 → 失败重试不会重复花钱。
4. **并发**：一个剧本同时只允许一个 `running` 的 run，避免两个 Agent 抢同一个 shot。

### 新增路由（`server/index.js`）

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/agents` | 剧组名册 |
| POST/PUT/DELETE | `/api/agents/:id?` | 增删改岗位（含工具白名单、预算、自动开关） |
| POST | `/api/agent-runs` | 启动 `{agentId, scriptId, goal}` → `{runId}` |
| GET | `/api/agent-runs/:id` | 运行详情 + 全部步骤（刷新后能续上时间线） |
| GET | `/api/agent-runs?scriptId=` | 历史运行列表 |
| POST | `/api/agent-runs/:id/resume` | 确认/继续 `{approved:true, note}` |
| POST | `/api/agent-runs/:id/stop` | 停止 |
| POST | `/api/agent-runs/:id/retry` | 从某步重跑 `{fromSeq}` |
| GET | `/api/agent-runs/:id/stream` | **SSE** 实时事件 |

**SSE 事件协议**（与 `/api/run` 现有风格保持一致，前端复用 `runSSE` 那套逻辑）

```
event: step    data: {seq, role, tool, args, status, brief, ms}
event: ask     data: {seq, question, options, kind}      // 等待人工
event: budget  data: {steps, images, videos, deadlineMs} // 每步后刷新
event: done    data: {status, summary, artifacts}
event: fatal   data: {message}
```

## 八、风险与取舍

| 风险 | 应对 |
| --- | --- |
| 弱模型不守 JSON 格式，循环空转 | 严格 JSON 约定 + `extractObjects` 兜底 + 最多 2 次纠错；连续 3 步解析失败即软停止，提示换模型 |
| 生图生视频真花钱 | 默认半自动；`kind` 为 image/video 的工具强制确认；预算三重上限（步数/张数/条数）+ 截止时间 |
| 上下文膨胀导致越来越贵 | 只回摘要 `brief`；滑动窗口压缩旧步骤；每轮带固定 token 预算 |
| Agent 重复拆镜堆镜头 | 调 `split_shots` 前先查现存镜头数，沿用现有「覆盖前确认」逻辑 |
| `node:sqlite` 迁移风险 | 全部用 `CREATE TABLE IF NOT EXISTS` + `ensureColumn`，不动现有表结构，可回滚（git 干净状态已提交） |
| 打包后 Electron 环境差异 | `WEAVE_DATA_DIR` 已处理；P0 完成后跑一次 `npm run pack` + CDP 截图验收 |

## 九、验收标准（P0）

1. `npm run dev` 起服务，侧边栏出现「Agent 应用」，点进去看到 5 个预置岗位
2. 选「制片人」+ 已有剧本 + 目标「把这一章做成一集 8 镜的成片」→ 点启动
3. 时间线实时流出：思考 → 工具 → 观察，其中 `split_shots` 与 `extract_*` 真实写库
4. 分镜页刷新后能看到新拆出来的 8 个镜头、角色页能看到新提取的角色
5. 触到生图工具时**停下来等确认**（半自动生效）
6. 中途刷新浏览器，`GET /api/agent-runs/:id` 能把时间线完整还原
7. `npm test`（smoke）通过；`npm run build` 无报错
8. CDP 截图存档：名册页 / 时间线运行中 / 确认卡 / 完成态

## 十、需要你拍板的三个点

1. **半自动默认**：默认「花钱前必须确认」是否符合你的预期？还是想要一键全自动（跑完再验收）？
2. **P0 范围**：P0 是否就按上表（读+文本类工具，生图/生视频留到 P1）？如果你更想先看到"出片"，我可以把 `batch_images`/`export_movie` 提前进 P0，但没有确认闸门就直接花钱。
3. **入口位置**：Agent 应用放侧边栏常驻，还是并进「生产线」页做成一个标签页？
